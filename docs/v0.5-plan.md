# v0.5 开发计划 — 后续 2-4 周

> v0.4 (`POST /parametric-blocks` + 4 步 wizard + 真联调) 已发, 8 commit push 到 `v0.2-development`。
> 本文件写 v0.5 阶段**具体做什么**、**先做哪个**、**怎么算做完**。高层优先级 (P0/P1/P2) 看 `docs/ROADMAP.md` §4.3, 这里是落地拆解。

## 现状 (v0.4 收尾)

- 用户能在 `localhost:5173/parametric` 走 4 步拿 GLB, 链路 Vite → API → Celery → MinIO 写真实。
- `block_generator.py` 支持 3 system (lego/duplo/feile) × 4 kind (brick/plate/tile/slope) × 任意 size。
- 5 测量字段 (`outer_pitch_mm` / `inner_pitch_mm` / `stud_diameter_mm` / `brick_height_net_mm` / `brick_height_total_mm`) 在 schema/api/CLI/DB 4 处对齐, vitest 锁住 wire 契约。
- slope 在 v0.4 是"借" brick 5 字段 (高边净高 / 高边总高), 见 `docs/parametric-block-guide.md` §3 v0.4 实现注。
- 13 张真照片 baseline 落 `tests/e2e/fixtures/real-photos/` (gitignored, 本地), 其中 1 块费乐 2x2 brick 完整 spec 验证通过 (`user-measured-brick-001` 落 fixture)。

## v0.5 候选 (按我推荐顺序)

### 候选 1: GLB 并排对比渲染 — 优先做这个

**动机**: 现在用户拿 GLB 但没法直观看到"模型对不对"。拍实物 4 视角照片 + 量 5 数字 → 跑出 GLB → 跟原照片半透叠在一起 → 0.2mm 偏差一目了然。这是 v0.4 的"spec 验证"留的尾巴 (ROADMAP §4.3 P0), 不做完用户没法拍 1 块验证 spec。

**交付物**:
- 新工具 `tools/compare_spec.py` (CLI) — 输入 GLB + 1 张照片 → 输出 `docs/validation/{part_id}-side-by-side.png` (半透叠加 + bbox 对齐)。
- App 端 PreviewStep 第 5 步: 可选上传实物照片 (1 张就够) → 跟 GLB 半透叠 → 偏差可见。
- 写 1 个 e2e test: 上传 GLB + 1 张 fixture 照片 → 验证生成的 PNG 跟 reference 偏差 < 5% 像素级 (BBox 对齐基础)。

**依赖**: 无 (只读 GLB + 照片, 不动 API)。
**工作量**: 2-3 天 (CLI 半天, App 端改造 1 天, e2e + 调优半天)。
**怎么算完**: 拿 feile 2x2 brick (实测过 spec 的那块) 跑一遍, 截图存 `docs/validation/feile-2x2-brick-measured-side-by-side.png`, 人眼看一眼"模型跟照片对得上"。

### 候选 2: 拍清单续拍 — 跟候选 1 一起做

**动机**: `docs/shoot-priorities.md` 列了 7 块 (费乐 1x1 / 2x4 / plate / tile / slope + DUPLO 2x2 + LEGO 2x4), 跨 system × kind 覆盖度从 25% 提到 100%。拍 + 量 + 走 App 是用户手上的活, 但 GLB + spec 落 fixture 是开发侧的活。

**交付物**:
- 7 个 `tests/e2e/fixtures/real-bricks/{system}-{size}-{kind}-measured/` 目录, 每个含 GLB + spec.json + preview.png + side-by-side.png (用候选 1 工具生成)。
- `docs/brands.md` 跟踪每个品牌的公开 spec 来源 + 实测偏差, 跟 ROADMAP §3 表格对齐。

**依赖**: 候选 1 (需要 GLB 对比工具才能产 side-by-side)。
**工作量**: 用户手上 1-2 天拍照 + 量尺寸 (5 测量每块 5 分钟), 我跑 measure_block + 候选 1 工具每块 2 分钟, 7 块共 30 分钟。
**怎么算完**: 4×2 矩阵 (system × kind 主要几种) 至少每格有 1 个 fixture, 实测偏差全 ≤ 0.2mm。

### 候选 3: slope 专属 5 字段 — v0.5.1 候选

**动机**: 现在 slope 借 brick 5 字段 (高边净高 / 高边总高 / 把 stud 当高边最深凸点), 量法别扭。slope 几何是楔形, 应该有专属 5 字段 (e.g. `slope_wedge_depth_mm` / `slope_wedge_height_mm` / `slope_unit_mm` / `slope_stud_diameter_mm` / `slope_stud_height_mm`)。文档里已经埋了 v0.4 fallback 注释 (`docs/parametric-block-guide.md` §3, capture-procedure §1.1)。

**交付物**:
- 后端 `_RAW_KEYS` 加 5 个 `slope_*` 字段 (跟 brick 5 字段并列, 不破坏现有)。
- `derive_spec_from_raw` 加 `if system == "feile" and kind == "slope"` 分支, 走 slope 专属解析 (rule: low-edge = 0, wedge height = brick_height_total, etc.)。
- 前端 `MeasurementsStep` 按 kind 动态显示 5 字段 (brick 走现有 5 字段, slope 走新 5 字段, 互斥)。
- 4 处契约全更新 (schema.ts / api.ts / parametric_blocks.py / measure_block.py), vitest 锁。
- `docs/measure-block-slope.svg` 已经画好, 但字段名要改成 `slope_*` 后对应版本。

**依赖**: 无 (纯扩展, 不破现有路径)。
**工作量**: 1-2 天 (后端字段 + 解析半天, 前端动态字段半天, vitest 锁 + 文档半天)。
**怎么算完**: 1 块实物 slope 拍 + 量 5 数字 → 走 App → 出 GLB, 跟手算的楔形几何比对 spec 一致。

### 候选 4: 第二轮品牌扩 — 看情况

**动机**: 国产除了费乐还有 **摩比 (Bkids)** / **汇乐 (HuiLe)** / **谷雨 (GuYu)** 等大颗粒, 跟费乐节距 16mm 类似但凸点 / 高度可能略不同。如果用户手里有, 加几个 system 就能扩 spec 库。

**交付物**:
- 候选 1+2 跑完, 用户拿着 1 块费乐 + 1 块摩比同时拍, 走 App, 验证 5 数字能不能精确覆盖两个品牌 (不行就加 system)。
- BlockGenerator 加 1-3 个新 system (`moby` / `huile` / `guyu`) + 公开 spec。

**依赖**: 候选 1+2 (需要对比工具 + 已有 spec 库做 baseline)。
**工作量**: 半天 / 品牌 (假设用户能提供 1 块实测 + 公开 spec 文档)。
**怎么算完**: 每个新品牌的 1 块实测 spec 偏差 ≤ 0.3mm (国产一致性比 LEGO 差, 放宽到 0.3)。

## 候选 5: 长期 (v0.6+)

- 零件库 CRUD (Part / Variant / Color) — 用户存自己 brick 库, 跨 capture 复用
- 网格手动编辑 (R3F) — design §5.3 范围
- round / technic brick 支持 — 扩 block_generator 6+ kind
- 拼搭规则引擎 — 接触面匹配 / 卡扣力 / 稳定性
- AI 灵感生成 (text → assembly) — 依赖零件库

不排进 v0.5, 候选 1+2+3 跑通后再说。

## 推荐执行顺序

1. **候选 1 + 2 并行** — 候选 1 是工具 (半天), 候选 2 是数据 (用户拍 + 我跑)。边做候选 1 边给候选 2 出 side-by-side, 7 块跑完 spec 库填到 75% 覆盖。
2. **候选 3 单开** — 1-2 天纯扩展, 跟候选 1+2 无依赖, 可以在候选 2 跑期间并行做。
3. **候选 4 按需** — 用户手里有别的品牌才开, 没就跳过到 v0.6+。

## 风险 + 注意事项

- **候选 1 半透叠的 bbox 对齐**: 实物照片分辨率不一, 跟 GLB (mm 单位) 缩放对齐是工程难题。MVP 用"按 GLB bbox 等比缩放照片到 bbox 内"简化, 后续可上 perspective homography。
- **候选 2 拍 7 块**: 用户手上能拍就拍, 拍不了哪块就先跳过, 不阻塞。13 张真照片已经在 fixtures, 候选 2 是扩展不是替代。
- **候选 3 slope 字段名**: 选名要跟 `brick_*` / `plate_*` / `tile_*` 风格一致 (e.g. `slope_wedge_height_mm` 而不是 `slope_h_mm`)。所有 4 处契约同步改。
- **跨任务字段名契约**: 任何 v0.5+ 字段改动, 都得 4 处同步 (`schema.ts` / `api.ts` / `parametric_blocks.py` / `measure_block.py`)。改前先在 `docs/parametric-block-guide.md` §8 记一笔。
